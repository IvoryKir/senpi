## 2026-10-26 - Exhausted extra usage downgrades only a requested legacy window, visibly (senpi#4065)

### What changed

- `errors.ts`: recognizes Claude Code's `You're out of extra usage` prefix (its `USAGE_LIMIT_ERROR_PREFIXES` entry) on the raw SDK failure text. When the attempt requested `[1m]` it is a long-context refusal; otherwise it keeps the verdict the SDK's error code gives (`billing_error` stays account billing) and, with no code, is non-retryable billing that keeps Claude's own reason, instead of an unclassified failure.
- `long-context-retry.ts`: passes the attempt's legacy-window flag to the shared classifier, exports `LONG_CONTEXT_FALLBACK_DIAGNOSTIC`, and `retryAtStandardWindowOnce` takes an optional `onFallback` called after the refusal is recorded, before the 200k retry.
- `auth-lane.ts`: `queryWithAuthLane` takes `onLongContextFallback`, called once when a refused `[1m]` request is retried at 200k, on the ambient retry and on managed failover.
- `session-stream.ts`: the resident lane passes `onLongContextFallback` through.
- `stream.ts`: the turn's assistant message records a `claude_sdk_oauth_long_context_fallback` diagnostic (`details.contextWindow`) when its request fell back, on the one-shot and the resident path.

### Why

- The exhaustion response names no window, so the refusal matcher missed it and a `[1m]` request failed instead of retrying at 200k. Treating it as a refusal without `[1m]` would downgrade requests that never asked for the legacy tier. The 200k retry is a safety net and must not be silent: the model stays selected, and the turn says its request ran at 200k.

### Why an extension could not handle it

- This is the builtin extension's request-scoped SDK failure classification and its own stream output.

### Expected merge conflict zones

- LOW: `errors.ts` `classifyErrorKind` (its first branch and its last return).
- LOW: `long-context-retry.ts` `retryAtStandardWindowOnce`; `auth-lane.ts` `AuthenticatedQueryInput` and the two retry call sites; `stream.ts` the two message sources.

## 2026-10-26 - A request retried at 200k shows a transcript notice (senpi#4065)

### What changed

- `components/continuity-notice.ts`: `ContinuityNoticeTracker.noticeFor` renders a muted line for the `claude_sdk_oauth_long_context_fallback` diagnostic: Claude refused the 1M window and the request was retried on the same model at 200k.

### Why

- A window fallback changes what the model can see; the user must be told rather than find out from compaction.

### Why an extension could not handle it

- The continuity notices are rendered by interactive mode from the assistant message's diagnostics.

### Expected merge conflict zones

- LOW: the diagnostic type constants and the first checks in `noticeFor`.
