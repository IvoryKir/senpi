### Fixed
- Provider error text in `fallback.log` and in a `model_config_error` turn is redacted for every credential shape a gateway echoes: authorization, key and token headers, cookies, JSON fields (nested or escaped), URL query parameters, `sk-`/`sk-ant-` keys, GitHub tokens, AWS access key ids and JWTs ([#4283](https://github.com/code-yeongyu/senpi/pull/4283))
- A provider or gateway answering that it does not serve the configured model (`model_not_found`, `unknown provider for model`, Anthropic's `not_found_error` naming the model, or Google's `models/<id> is not found`) no longer retries or walks the fallback chain onto another provider, whatever HTTP status wraps it (a 502 or 503 included): the turn fails with the redacted provider body, `errorCause: { type: "model_config" }`, and one `model_config_error` session event and fallback-log line per model and session. On a model the session already fell back to, the turn ends there instead of trying the next rung ([#4283](https://github.com/code-yeongyu/senpi/pull/4283))

## 2026-10-25 - model_not_found is a configuration error, never a fallback (senpi#4282)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `_isRetryableError` and `_isHardErrorFallbackEligible` exclude a model configuration error (`retry-fallback/model-config-error.ts`: `model_not_found`, `unknown provider for model`, an Anthropic `not_found_error` whose message names the model, a Google `models/<id> is not found`), matched by body whatever status wraps it; at `message_end`, before the message is queued for persistence, it is redacted and marked `errorCause: { type: "model_config", model }`, and reported once per model and session as a `model_config_error` session event and a `fallback.log` warning. `AgentSessionEvent` gains `model_config_error`. A configuration error on a model the session already fell back to ends the turn too: no rung after it is tried.
- `packages/coding-agent/src/core/sensitive-output.ts`: `redactSecrets` covers every credential shape (header lines, JSON fields plain/nested/escaped, URL queries, cookies, `sk-`/`sk-ant-`, GitHub tokens, AWS access key ids, JWTs) and keeps model ids, error codes and request ids readable; `retry-fallback/log.ts` and the model configuration error use it.

### Why

- A gateway that stopped serving a configured model answered `400 model_not_found` for every rung; the hard-error walk silently finished the turn on another provider's model, so work that needed that model family ran on a different one with only a log line to show for it.

### Why an extension could not handle it

- Retry and fallback eligibility is decided inside `AgentSession` before any extension sees the failed turn.

### Expected merge conflict zones

- LOW: the `_isRetryableError` and `_isHardErrorFallbackEligible` predicate lists, the `message_end` pre-queue block, and the not-handled block after the retry decision in `agent-session.ts`; one line in the `AgentSessionEvent` union.

## 2026-10-25 - errorCause names a model configuration error (senpi#4282)

### What changed

- `packages/ai/src/types.ts`: `AssistantMessage.errorCause` also accepts `{ type: "model_config"; model: string }`.

### Why

- Clients and task hosts read a typed cause instead of matching provider text when a configured model id is not served by its route.

### Why an extension could not handle it

- The assistant message shape is defined here.

### Expected merge conflict zones

- LOW: the `errorCause` field of `AssistantMessage`.
