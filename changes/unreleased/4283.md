## 2026-10-25 - model_not_found is a configuration error, never a fallback (senpi#4282)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `_isHardErrorFallbackEligible` excludes a model configuration error (`retry-fallback/model-config-error.ts`); a turn that ends on one is redacted, marked `errorCause: { type: "model_config", model }`, and reported once per model and session as a `model_config_error` session event and a `fallback.log` warning. `AgentSessionEvent` gains `model_config_error`.

### Why

- A gateway that stopped serving a configured model answered `400 model_not_found` for every rung; the hard-error walk silently finished the turn on another provider's model, so work that needed that model family ran on a different one with only a log line to show for it.

### Why an extension could not handle it

- Retry and fallback eligibility is decided inside `AgentSession` before any extension sees the failed turn.

### Expected merge conflict zones

- LOW: the `_isHardErrorFallbackEligible` predicate list and the not-handled block after the retry decision in `agent-session.ts`; one line in the `AgentSessionEvent` union.

## 2026-10-25 - errorCause names a model configuration error (senpi#4282)

### What changed

- `packages/ai/src/types.ts`: `AssistantMessage.errorCause` also accepts `{ type: "model_config"; model: string }`.

### Why

- Clients and task hosts read a typed cause instead of matching provider text when a configured model id is not served by its route.

### Why an extension could not handle it

- The assistant message shape is defined here.

### Expected merge conflict zones

- LOW: the `errorCause` field of `AssistantMessage`.
