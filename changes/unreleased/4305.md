## 2026-10-26 - Fork files are built atomically and a header catch-up keeps its prefix (senpi#4295)

### What changed

- `packages/coding-agent/src/core/session-manager.ts`: `forkFrom` builds the fork through `replaceFileAtomically` (temp file, fsync, rename) instead of an exclusive header write followed by one `appendFileSync` per entry; an existing target still fails with `EEXIST`. When the post-close catch-up append of `_writeHeaderAsync` fails, the file is kept and cut back to the bytes known whole (`_keepCaughtUpPrefix`), the transcript counts as flushed, and the entries that append carried are written, one line each, before the next append.

### Why

- A full disk part-way through `forkFrom` left a half-copied fork in the session list. A failed catch-up deleted the whole new file, including the header and entries already on disk.

### Why an extension could not handle it

- Both writes run inside `SessionManager`.

### Expected merge conflict zones

- MEDIUM: `packages/coding-agent/src/core/session-manager.ts`, `_writeHeaderAsync` and the flushed append in `_persist`.
- LOW: `forkFrom` file creation.
