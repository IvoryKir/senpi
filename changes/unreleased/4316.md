## 2026-10-27 - external_directory classifies the path the tool opens (senpi#4311)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/permission-system/parsers.ts`: `withExternalDirectoryRequests` maps each raw argument through the resolver its tool uses before classifying it (write/edit/ls/find/glob: `resolveToCwd`; apply_patch: `resolvePatchPath`; grep: `resolveToCwd` plus the `:L<a>-L<b>` selector prefix; `multiedit`: raw and resolved; monitor: raw). grep `path` arrays are classified element by element.
- `packages/coding-agent/src/core/extensions/builtin/permission-system/prompt.ts`: the external-directory prompt prefers the resolved pattern over the call's raw `filepath`.

### Why

- The check classified the raw text while the tools open the normalized path, so `@/abs/x`, `file:///abs/x`, Unicode-space spellings and grep arrays or line selectors reached files outside the workspace with no `external_directory` ask under the narrower presets.

### Why an extension could not handle it

- The parser registry is the permission system's own input to every decision (tool_call hook and codemode dispatch); an extension cannot replace a builtin parser.

### Expected merge conflict zones

- LOW: `parsers.ts` parser registrations (fork-only permission system).
