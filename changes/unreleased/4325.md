## 2026-10-26 - The engine classifies every inbound RPC record and advertises the table (senpi#4319)

### What changed

- `packages/coding-agent/src/modes/rpc/rpc-method-class.ts` (fork-only, new): `RPC_METHOD_CLASS` gives every
  `RpcInboundRecord["type"]` a class (`observe`, `drive`, `answer`, `thread`, `device_admin`, `connection_local`) or a
  pure function of the record; it `satisfies` a mapped type over the union, so a record type added without a class
  fails the typecheck. `export_html`/`export_jsonl` are `observe` without `outputPath` and `device_admin` with it;
  `append_session_entry` is `drive` only for a user-authored message entry, decided by a table exhaustive over
  `SessionEntry["type"]`. `classifyRpcMethod(record)` reads own keys only and returns `undefined` for anything it
  cannot classify; `rpcMethodPermitted(record, granted)` refuses an unclassified record whatever is granted and never
  permits `connection_local`. The digest is sha256 of the sorted `type=class\n` lines, `type=dynamic` for a function
  entry.
- `packages/coding-agent/src/modes/rpc/rpc-host-command-types.ts`, `rpc-host-response-types.ts`: the new observing
  command `get_rpc_method_classes` and its answer `{ version, digest, classes }` (`dynamic` for a function entry).
- `packages/coding-agent/src/modes/rpc/rpc-protocol-info-types.ts`: optional `rpc_method_classes: { version, digest }`.
- `packages/coding-agent/src/modes/rpc/host-capabilities.ts`, `connection-handler.ts`, `session-router-routing.ts`:
  multi-session and classic hosts advertise the `rpc_method_classes` capability and field, and answer
  `get_rpc_method_classes`.
- `packages/coding-agent/src/modes/rpc/host-observe-request.ts`: `get_rpc_method_classes` with `observe: true` is an
  observing read.

### Why

- A client that relays requests for someone other than the local user needs an engine-owned answer to which
  records it may accept from them; a list kept outside the engine drifts the moment a method lands.

### Why an extension could not handle it

- The table has to be checked against the engine's own inbound record union at compile time and answered by the
  host's RPC router, which extensions do not own.

### Expected merge conflict zones

- LOW: the `get_protocol_info` answers in `connection-handler.ts` and `session-router-routing.ts` (one field, one
  capability), the `get_subscription_limits` neighbours in both handlers and in the command/response unions, and
  `multiSessionHostCapabilities`.

### Added
