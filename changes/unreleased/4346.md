## 2026-10-26 - Host lists derive from the method table; one schema validates every inbound record (senpi#4324)

### What changed

- `packages/coding-agent/src/modes/rpc/rpc-method-class.ts` (fork-only): `RPC_METHOD_TRAITS`, exhaustive over
  `RpcInboundRecord["type"]` beside `RPC_METHOD_CLASS`, gives each type the traits its class does not decide
  (`observing_read`, `read_only`, `new_work`); a trait typechecks only on the classes it can be true of. The derived
  sets `RPC_OBSERVING_METHODS`, `RPC_ACTIVITY_NEUTRAL_METHODS` and `RPC_NEW_WORK_METHODS` combine class and trait.
- `packages/coding-agent/src/modes/rpc/host-observe-request.ts`, `session-command-activity.ts`, `host-idle-handover.ts`:
  the hand-kept observing, activity-neutral and new-work lists are replaced by the derived sets. Membership is unchanged
  except that the four host-level `observe` reads (`get_protocol_info`, `get_rpc_method_classes`,
  `get_subscription_limits`, `list_sessions`) join the activity-neutral set; they are answered before any session
  lookup, so no session's activity changes.
- `packages/coding-agent/src/modes/rpc/rpc-inbound-schema.ts` (fork-only, new): one TypeBox schema per inbound record
  type, exhaustive and checked against the record types at compile time (accepts every well-typed record, names the
  same fields, requires the same ones), and `validateRpcInboundRecord(record)` (`{ ok: true }` or `{ ok: false, reason }`)
  built from it plus the existing field bounds. Every field is bounded (`RPC_INBOUND_LIMITS`: identifiers, paths, text
  and credentials by length; counts as non-negative integers; lists, images and free-form records by size), and the
  validator, its result type and the limits are exported from the package root (`src/index.ts`).
  `rpcMethodBaseClass(type)` derives the lists from each type's bare-record class, so a record-dependent rule decides
  only who may send a record, not what the method is; `hasRpcMethod` replaces the two set casts. Question answers are bounded for validated callers: 64 answers, 64
  selected labels each, labels at most `MAX_RPC_MESSAGE_CHARACTERS`. The local connection does not run it.
- `packages/coding-agent/test/supervisor-import-graph.test.ts`: the supervisor graph counts `rpc-method-class` as a
  named leaf (type-only imports plus `node:crypto`).

### Why

- Three hand-kept lists had drifted from each other and from the method table, and only a few record types had a
  runtime validator; a caller acting for someone other than the local user needs one for every type.

### Why an extension could not handle it

- The lists and validators are the host's own admission and lifecycle code, checked against the engine's inbound
  record union at compile time.

### Expected merge conflict zones

- LOW: the list definitions in `host-observe-request.ts`, `session-command-activity.ts` and `host-idle-handover.ts`
  (a new type added to a hand list upstream must move into `RPC_METHOD_TRAITS`).

### Added
- RPC hosts derive their observing, activity-neutral and new-work command lists from the method class table, and `validateRpcInboundRecord` validates every inbound record type from one schema for callers acting for someone other than the local user ([#4324](https://github.com/code-yeongyu/senpi/issues/4324))
