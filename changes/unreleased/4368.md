## 2026-10-26 - Read the canonical agent directory without opening state (#4368)

### What changed

- `packages/coding-agent/src/cli/agent-dir-command.ts`: add `config agent-dir --json`, reporting the exact `getAgentDir()` result and its directory source, selection rule and branded prefix.

### Why

- The desktop must ask the same engine version that will run its sessions instead of copying the CLI's directory-selection policy. Part of desktop#4753; the reporter's billing-error root cause remains unproven.

### Why an extension could not handle it

- Directory selection must be available before settings, extensions, data-home checks or host startup. The command only reads selector inputs and filesystem layout; it creates no marker or state files.

### Expected merge conflict zones

- LOW: metadata-command routing before full CLI startup.

## 2026-10-26 - Handle directory metadata before startup side effects (#4368)

### What changed

- `packages/coding-agent/src/cli.ts`: handle `config agent-dir --json` before enabling compile caches or preparing a runtime snapshot.
- `packages/coding-agent/src/cli-main.ts`: handle the same command before cache setup and lazily import the full agent entry only afterward.

### Why

- A selector query must not initialize the directory whose location it is only being asked to report. Both the source launcher and compiled direct-entry path must obey that contract.

### Why an extension could not handle it

- The command decides the store before extension discovery and host admission.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/cli.ts` and `packages/coding-agent/src/cli-main.ts` startup dispatch.
