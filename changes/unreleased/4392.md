## 2026-10-26 - Python eval permission enforcement (senpi#4392, part of #4309)

### What changed

- `packages/senpi-codemode/src/kernels/py/interpose.py` and `packages/senpi-codemode/src/kernels/py/permission_bridge.py`: install Python API wrappers and synchronous, invocation-authenticated checks before user code. Cover process creation, mode-aware files and descriptors, filesystem mutations, listing, SQLite, loader sources, and package resources.
- `packages/senpi-codemode/src/kernels/py/permission-host.ts`, `packages/senpi-codemode/src/kernels/py/kernel.ts`, `packages/senpi-codemode/src/kernels/py/kernel-contract.ts`, `packages/senpi-codemode/src/kernels/py/kernel-tools-host.ts`, `packages/senpi-codemode/src/kernels/py/transport.ts`, and `packages/senpi-codemode/src/kernels/py/prelude.py`: carry host-minted tokens through cells and callbacks, publish read-only mapped authority words, cancel pending checks, and gate replacement on observed interpreter exit.
- `packages/senpi-codemode/src/bridge/permission-check.ts` and `packages/senpi-codemode/src/bridge/http-server.ts`: add the nonce-bound permission-check route without using the owner's bridge bearer.
- `packages/senpi-codemode/src/kernels/js/permission-slots.d.mts`: add `read` and `ls` to the shared operation type without changing the JavaScript slot protocol.
- `packages/senpi-codemode/src/kernels/shared/subprocess-contract.ts`, `packages/senpi-codemode/src/kernels/shared/subprocess-kernel.ts`, `packages/senpi-codemode/src/kernels/rb/kernel.ts`, and `packages/senpi-codemode/src/kernels/jl/kernel.ts`: refuse Ruby and Julia cells while enforcement is active, including queued-cell admission.
- `packages/senpi-codemode/src/kernels/py/permission-core.md`: document transport, lifetime, engine provenance, and integration ownership. The Python API matrix, lifetime tests, and unsupported-kernel tests provide RED/GREEN coverage.
- Review fold: capture private stdlib dependencies and JSON/socket primitives; cover native `posix`/`nt` aliases, direct builtin/dynamic extension loading, path metadata mutations, and base-descriptor registry writes. Keep inactive copied contexts and background tasks usable after their originating cell settles. Load engine assets without bytecode-cache writes and keep the raw FileIO constructor out of the adapter's MRO. The import registries (`sys.modules`, `sys.meta_path`, `sys.path_hooks`) are never replaced: CPython's C-level import reads the interpreter's own module dict rather than the `sys` attribute, so any substitute diverges from it and modules first imported in a cell become invisible to C importers. Cells reach the registries only through views that refuse mutation, and every enforced decision re-verifies that they are still the interpreter's own objects with their captured entries.
- `packages/senpi-codemode/test/gate/allowlist.json`: approve the 468 measured additive contracts owned by this PR without editing the frozen compatibility baseline or inherited stack approvals.

### Why

- Python code could previously perform operations that the user's configured tool deny rules would refuse. Kernel-tool callbacks also need their own authority lifetime rather than borrowing the current cell.
- Revocation must invalidate new operations immediately and must observe interpreter exit before admitting a replacement. Ruby and Julia cannot yet provide equivalent API coverage and therefore fail closed only when enforcement applies.

### Why an extension could not handle it

- Interposition must precede user code inside the interpreter, while invocation tokens, the bridge, authority publication, and process retirement belong to the kernel host. The permission extension supplies the decision service and reload events through the typed seam; it cannot retrofit these boundaries from outside a running cell.

### Expected merge conflict zones

- Python bootstrap, init/run frames, callback dispatch, and retirement in the listed Python files; the HTTP bridge route table; Ruby/Julia startup options and shared subprocess admission.
- The `CellOperation` union may overlap the JavaScript API-coverage stack member. No slot layout or transition changes are included.
- Known limitation: reads performed by the runtime's native module resolver (bare packages, tsconfig aliases, package.json #imports, symlinked packages) are not covered by this work; tracked in #4380.

## 2026-10-28 - Python cells send the executed path spelling (senpi#4392)

### What changed

- `packages/senpi-codemode/src/kernels/py/interpose.py`: every path request now carries two fields, `path` (the spelling as written, byte-for-byte) and `executedPath` (the string the operating system receives: an absolute spelling as is, a relative spelling joined onto the interpreter's current directory with the captured `os.path.join`, never collapsed or resolved in the interpreter). Descriptor-based listings carry the recorded directory the same way. Python sends no canonical form: `os.path.realpath` rebuilds a path from the request's own components and differs from the native resolution on case and Unicode-form aliases, so the host canonicalizes the executed path on its resolver worker. A spelling that is not valid UTF-8 cannot travel losslessly and is refused as uncheckable before any decision is requested. `os.getcwd`, `os.path.isabs` and `str.encode` join the privately captured dependencies.
- `packages/senpi-codemode/src/bridge/permission-check.ts`: the loopback `/permission_check` route admits `executedPath` as a string next to `path`; every other input field is still dropped, so a kernel cannot hand the host a canonical form over this route.
- `packages/senpi-codemode/src/kernels/py/permission-core.md`: documents the two-field contract.
- `packages/senpi-codemode/test/py-kernel-permission-path-identity.test.ts`: the Python dimension of the rule-spelling x request-spelling table (symlinked directory and file, relative spelling, `link/../x`, `os.chdir`, case and Unicode-form aliases where the volume folds them, directory listings through a path and through a directory descriptor, the lossy-bytes refusal), under an active deny and an inactive kernel.

### Why

- A rule written on one spelling of a file must reach the same file under every spelling a Python cell can open it with, including a relative spelling anchored to a directory the cell changed into; the host can only do that from the executed string, which the interpreter alone knows.

### Why an extension could not handle it

- The executed spelling is known only inside the interposed Python operation; the bridge is the only route a decision can travel on.

### Expected merge conflict zones

- `packages/senpi-codemode/src/kernels/py/interpose.py` (`install` captures, `path_call`) and `packages/senpi-codemode/src/bridge/permission-check.ts` (input field admission).

### Added

- Enforce host-supplied deny decisions inside Python eval cells and callbacks, including file modes, descriptor grants, process APIs, SQLite, module sources, and package resources; refuse Ruby and Julia cells while enforcement is active ([#4392](https://github.com/code-yeongyu/senpi/pull/4392), part of #4309).
- Revoke Python invocation authority immediately and wait for observed interpreter retirement before admitting a replacement ([#4392](https://github.com/code-yeongyu/senpi/pull/4392)).
- Keep Python permission checks intact after stdlib rebinding, guard native aliases and direct extension entry points, and preserve cross-cell background I/O when no deny applies ([#4392](https://github.com/code-yeongyu/senpi/pull/4392)).
- Leave the interpreter's own import registries in place while guarding them, so C-level imports such as `pickle`, `datetime.strptime` and `xml.etree.ElementTree` keep working inside Python cells ([#4392](https://github.com/code-yeongyu/senpi/pull/4392)).
- Known limitation: reads performed by the runtime's native module resolver (bare packages, tsconfig aliases, package.json #imports, symlinked packages) are not covered by this work; tracked in #4380.
- Python eval cells now send the path they execute in addition to the path as written, so permission rules for `read`, `edit`, `list` and `grep` paths apply to the same file under every spelling a Python cell resolves to it, including relative spellings after `os.chdir`; a path spelling that is not valid UTF-8 is refused as uncheckable ([#4392](https://github.com/code-yeongyu/senpi/pull/4392)).

## 2026-10-28 - A mount point listed more than once no longer degrades the whole mount snapshot (senpi#4392)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/permission-system/mount-table.ts` (split out of `alias-detector.ts`, which was past the file size ceiling): the `mount`/`/proc/self/mounts` parser and `readMountTable`. A mount point listed more than once keeps its last line: on Linux `/proc/self/mounts` lists mounts in attach order, so that line is the mount visible at the point (stacked mounts such as `binfmt_misc` over its `autofs` trigger are ordinary on systemd hosts). Darwin `mount` carries no such ordering contract, so a repeated point is recorded in the new `ambiguous` list of the snapshot instead of degrading it. `degraded` now means a rejected line or a missing root entry only.
- `packages/coding-agent/src/core/extensions/builtin/permission-system/alias-detector.ts`: a component whose longest-matching mount point is ambiguous is unconfirmed (`mount-point-ambiguous:<point>`), so paths beneath such a point still read as alias in play, while every other path on the host is confirmed as before and the breaker keeps its per-volume key. `path-identity-host.ts`, `path-identity-worker.ts` and `path-identity-protocol.ts` import the snapshot types from the new module.
- `packages/coding-agent/test/permission/mount-table.test.ts`: a Linux fixture with stacked mounts, the last-wins proof through the detector in both stacking orders, the breaker key under a stacked mount, and the darwin ambiguity rows. `evaluate-identity.test.ts`: the `external_directory` service-boundary row now covers the direction only the inode matcher reaches (rule written through a link, request on the real path), which fails on the pre-fix evaluator.

### Why

- On a Linux host with stacked mounts every path read as alias in play and the breaker lost its per-volume key, which costs resolver calls and breaker isolation without any gain in safety; the visible mount is known from the table's order.

### Why an extension could not handle it

- The mount snapshot is read and validated inside the permission system's resolver worker.

### Expected merge conflict zones

- `alias-detector.ts` (the parser moved out), `path-identity-protocol.ts` (`MountSnapshot` import).
