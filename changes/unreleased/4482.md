## 2026-10-27 - The input event says whether the user or an agent sent the input (senpi#4482)

### What changed

- `packages/coding-agent/src/core/extensions/types.ts`: new exported `InputAttribution = "user" | "agent"`; `InputEvent` gains a required `attribution` field. `source` keeps its meaning (the channel the input arrived on).
- `packages/coding-agent/src/core/extensions/runner.ts`: `emitInput` takes an optional sixth argument `attribution`, defaulting to what `source` implies (`extension` => `"agent"`, otherwise `"user"`), and puts it on every `input` event.
- `packages/coding-agent/src/core/extensions/index.ts`: re-exports `InputAttribution`.

### Why

- An extension that must react only to the person's own messages (OmO computer use lifting its Esc stop on the user's next message, code-yeongyu/oh-my-openagent#11459) could not tell typed or RPC-client input from input an extension, tool or subagent sends on the same channel (senpi#4471).

### Why an extension could not handle it

- Only the session knows who started an input; the `input` event carried just the channel, and `source: "extension"` covers both an extension's own sends and a person's answer delivered through the extension API.

### Expected merge conflict zones

- LOW: the `InputEvent` interface and the `InputSource` alias in `types.ts`; `emitInput`'s signature and event literal in `runner.ts`; the `Input*` re-export block in `extensions/index.ts`.

## 2026-10-27 - Input events carry the input origin's attribution (senpi#4482)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: both `emitInput` calls pass `inputAttributionOf(origin)`: `prompt()` uses `originOf(options)`, and `_runInputHandlers` takes the origin `_admitQueuedInput` computes for steer and follow-up input. A person's answer sent through the extension API therefore reports `"user"` with `source: "extension"`.
- `packages/coding-agent/src/core/input-origin.ts`: `inputAttributionOf(origin)` maps origin `person` to `"user"` and `extension` / `engine` to `"agent"`.

### Why

- The attribution must agree with the session's existing input-origin classification (senpi#3853) that already decides attended input and held-input release, instead of a second rule per call site (senpi#4471).

### Why an extension could not handle it

- The origin is decided inside `AgentSession` from internal options (`inputOrigin`, the runner's answer token) that extensions never see.

### Expected merge conflict zones

- LOW: the `input-origin.ts` import, the `_runInputHandlers` signature and its `emitInput` call, the `emitInput` call in `prompt()`, and the `_runInputHandlers` call in `_admitQueuedInput` in `agent-session.ts`.

## 2026-10-27 - Export the input attribution type (senpi#4482)

### What changed

- `packages/coding-agent/src/index.ts`: re-exports `InputAttribution` beside `InputEvent` and `InputSource`.

### Why

- Extension authors type their `input` handlers against the package's public types (senpi#4471).

### Why an extension could not handle it

- The package's public type surface is defined here.

### Expected merge conflict zones

- LOW: the extension type export list in `src/index.ts`.
