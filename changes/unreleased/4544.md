## 2026-10-27 - Compaction, provider-required and re-authentication texts name a step every client can take (senpi#4329)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: every `compaction_end.errorMessage` failure (manual "Nothing to compact" and "Already compacted", manual and requested compaction failures, extension-callback compaction failures, auto-compaction and overflow-recovery failures) is built by `formatCompactionFailure` from the new fork-only `compaction-failure-text.ts`: the existing lead (`Compaction failed: `, `Auto-compaction failed: `, `Context overflow recovery failed: `), the cause class with one next step, then `Cause: <raw>`. The thrown errors and `OVERFLOW_RECOVERY_EXHAUSTED_MESSAGE` are unchanged. The OAuth re-authentication refusal (`_getRequiredRequestAuth` and `_assertModelReadyForTurn`) says to sign in to the provider again instead of naming `/login`.
- `packages/coding-agent/src/core/auth-guidance.ts`: `getProviderLoginHelp` and `formatNoModelSelectedMessage` name the step (connect a provider by signing in or adding an API key; select a model) without the TUI-only `/login` and `/model` commands. The texts still open with `No API key found for <provider>.` and `No model selected.`
- `packages/coding-agent/src/core/auth-storage.ts`: the unused-login notice and the skipped Anthropic subscription migration error say to sign in again instead of naming `/login`.

### Why

- `packages/coding-agent/src/core/agent-session.ts`: the compaction failure text was the raw cause alone and named no step; the auth refusals reach RPC and desktop clients, which have no `/login` command.
- `packages/coding-agent/src/core/auth-guidance.ts`, `packages/coding-agent/src/core/auth-storage.ts`: these texts reach RPC `prompt` responses, `provider_required` events and startup notices on every surface.

### Why an extension could not handle it

- `packages/coding-agent/src/core/agent-session.ts`, `packages/coding-agent/src/core/auth-guidance.ts`, `packages/coding-agent/src/core/auth-storage.ts`: the texts are built in session compaction lifecycle, turn admission and credential storage, which run before or outside any extension hook.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/core/agent-session.ts` the `compaction_end` emits in `compact`, `applyCompaction`, `_runAutoCompaction` and the extension compaction callback, and the two `Authentication failed for` throws.
- LOW: `packages/coding-agent/src/core/auth-guidance.ts` `getProviderLoginHelp` and `formatNoModelSelectedMessage`.
- LOW: `packages/coding-agent/src/core/auth-storage.ts` `unusedLoginNotices` and the migration-skip error.

## 2026-10-27 - provider_required warning adds the TUI commands (senpi#4329)

### What changed

- `packages/coding-agent/src/modes/interactive/interactive-mode.ts`: the `provider_required` warning appends `PROVIDER_REQUIRED_TUI_HINT` (`/login` to sign in or add an API key, `/model` to select a model) to the shared notice, which no longer names TUI commands.

### Why

- `packages/coding-agent/src/modes/interactive/interactive-mode.ts`: the shared notice became surface-neutral for RPC and desktop clients; TUI users keep the exact commands.

### Why an extension could not handle it

- `packages/coding-agent/src/modes/interactive/interactive-mode.ts`: the warning is rendered by the built-in session event handler.

### Expected merge conflict zones

- LOW: `packages/coding-agent/src/modes/interactive/interactive-mode.ts` the `provider_required` case of `handleEvent` and the module constants.
