## 2026-10-29 - Named private descriptors reach exactly one engine launch (senpi#4771)

### What changed

- `packages/coding-agent/src/private-fds.ts` (new): reads and removes `SENPI_PRIVATE_FDS` (a JSON object mapping each name to a descriptor or to `null`) at startup, before anything can spawn. `null` means the launcher declared the channel but this spawn path has no descriptor (for example a Windows shell shim). The whole table is checked before any descriptor is adopted: names are lowercase ASCII, descriptors are unique integers from 5 to 64 and must be a socket or FIFO; any other value rejects the table. Windows adopts no descriptor and keeps only declarations. `privateChannelDeclared(name)` is true for a descriptor or a `null` entry. `takeInheritedPrivateChannel(name)` claims a named duplex once; the capture is shared through a process-wide symbol, so the bundled CLI and the public subpath see the same claims.
- `packages/coding-agent/src/private-fd-spawn.ts` (new): `spawnWithPrivateFds` / `preparePrivateFdSpawn` add the captured descriptors to one explicit engine spawn's stdio table, restore the table only in that child's environment, and close this process's copies after the spawn. `null` entries forward hop to hop like descriptors; a shell or Windows hop receives every name as `null`. The supervisor-to-engine hop is final (`SENPI_PRIVATE_FDS_FINAL`): the engine claims its channels but never forwards them, so a host it starts later inherits neither the table nor the descriptors.
- `packages/coding-agent/src/cli.ts`, `packages/coding-agent/src/cli-main.ts`, `packages/coding-agent/src/bun/cli.ts`: import the capture first; the Bun re-exec and the full-CLI child forward through the helper.
- `packages/coding-agent/package.json`: exports `./private-fds`.

### Why

- A launcher (the desktop app) needs a private, engine-lifetime duplex to one engine generation. The only extra startup descriptor was MCP enrollment, which closes after its bounded exchange (#4749).

### Why an extension could not handle it

- The descriptors must cross the CLI re-exec, `host ensure`, the supervisor and the engine spawn, all of which happen before any extension loads, and the table must leave the environment before unrelated children start.

### Expected merge conflict zones

- The first imports of `cli.ts`, `cli-main.ts` and `bun/cli.ts`; the re-exec block in `cli.ts`.

## 2026-10-29 - Ensure, supervisor and successor spawns forward named private descriptors (senpi#4771)

### What changed

- `packages/coding-agent/src/modes/rpc/host-ensure-start.ts`, `packages/coding-agent/src/modes/rpc/host-lifecycle-launch.ts`, `packages/coding-agent/src/modes/rpc/host-successor.ts`: the supervisor, engine and successor spawns go through `spawnWithPrivateFds`, so descriptors named by `SENPI_PRIVATE_FDS` reach the new engine generation and nothing else; the engine spawn is the final hop. A reused host receives nothing; a restarted engine needs a fresh launcher descriptor.
- `packages/coding-agent/src/modes/rpc/mcp-presenter-bootstrap.ts`: the inherited fd 4 adoption moved to `utils/inherited-duplex.ts` unchanged; `presenterBootstrapStream` calls it.

### Why

- Same as the entry above (#4749): the engine-lifetime channel must survive `host ensure` exiting.

### Why an extension could not handle it

- These spawns run in the ensure and supervisor processes, where no extension runs.

### Expected merge conflict zones

- The `spawn` imports and call sites in the three host files.

## 2026-10-29 - Shared inherited duplex adoption (senpi#4771)

### What changed

- `packages/coding-agent/src/utils/inherited-duplex.ts` (new): the Node socket / Bun file-stream adoption of an inherited pipe or socket, extracted from `mcp-presenter-bootstrap.ts` so MCP enrollment and named private descriptors share one implementation.

### Why

- One owner for inherited-descriptor adoption instead of two copies (#4749).

### Why an extension could not handle it

- It is used by core startup code before extensions load.

### Expected merge conflict zones

- None expected; new file.

### Added

- Launchers can pass named private duplex descriptors to one engine generation through `SENPI_PRIVATE_FDS`; extensions claim them once with `takeInheritedPrivateChannel` and check a declaration with `privateChannelDeclared` from `@code-yeongyu/senpi/private-fds`. Unrelated children and hosts the engine starts receive neither the table nor the descriptors, and Windows carries declarations only ([#4771](https://github.com/code-yeongyu/senpi/pull/4771), fixes [#4749](https://github.com/code-yeongyu/senpi/issues/4749)).
