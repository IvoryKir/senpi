## 2026-10-29 - A stored auth block with no deadline lists as blocked (senpi#4885, senpi#4365 follow-up)

### What changed

- `packages/coding-agent/src/core/credential-accounts.ts`: `storedSlotBlock` decides a slot's own stored block with the lane's selection predicate (`isAccountBlocked` for `anthropic-subscription`, `isSlotBlocked` otherwise) instead of a deadline-only copy. A stored `auth_error` with no `blockedUntil` (or a passed one) on a pool or Cursor CLI slot now lists `blocked: true, blockedReason: "auth_error"` with no `blockedUntil`; when the sidecar also holds a timed block, the deadline-free stored block wins so no expiry is borrowed.

### Why

- Selection skipped such a slot while the listing said `blocked: false`, so a client (the desktop lane resolver) could route a new session to an account senpi would never use (sisyphuslabs/omo-desktop-app#4203, the follow-up recorded in senpi#4365).

### Why an extension could not handle it

- The provider-neutral account listing is core; no extension hook reshapes `get_provider_accounts`.

### Expected merge conflict zones

- LOW: `slotBlocked` and its callers in `credential-accounts.ts` (senpi#4879 and senpi#4883 touch neighbouring account code).

## 2026-10-29 - Export the slot-selection block predicate (senpi#4885)

### What changed

- `packages/ai/src/auth/pool/select.ts`: the private `isBlocked` is exported as `isSlotBlocked`; `selectSlot` uses it unchanged.

### Why

- Account listings must answer "is this slot available" with the predicate selection uses, not a second copy that can drift (senpi#4365 follow-up).

### Why an extension could not handle it

- The predicate lives in the pool engine; callers outside it could only re-implement it, which is the bug.

### Expected merge conflict zones

- LOW: `isSlotBlocked` in `select.ts`.

## 2026-10-29 - Account selection uses the shared slot-block predicate (senpi#4885)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/cursor-cli-oauth/affinity.ts`: the private `isBlocked` copy is removed; `selectAccount` calls `isSlotBlocked` from `@earendil-works/pi-ai/auth/pool/select`. Behavior is unchanged (`auth_error` persists until re-login, other blocks until their deadline).

### Why

- The account listing now asks the same predicate, so selection and listing cannot drift again (senpi#4365 follow-up).

### Why an extension could not handle it

- The predicate is this builtin lane's own selection rule.

### Expected merge conflict zones

- LOW: the import line and `selectUnblocked` in `affinity.ts`.

## 2026-10-29 - Export the account-level block predicate (senpi#4885)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/affinity.ts`: `isAccountBlocked` is exported (unchanged) so the generic account listing decides this lane's stored blocks with the lane's own rule, which re-probes an auth block whose deadline passed (senpi#3264).

### Why

- One source of truth for "selection skips this account" (senpi#4365 follow-up).

### Why an extension could not handle it

- The predicate is this builtin lane's own selection rule.

### Expected merge conflict zones

- LOW: the `isAccountBlocked` declaration in `affinity.ts`.
